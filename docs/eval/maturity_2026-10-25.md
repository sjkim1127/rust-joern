# Rust Joern versus Joern — bounded status, 2026-10-25

Comparison target: **Joern 4.0.150 / PyJoern 4.0.150.4**, not an assertion about
the latest upstream release. A single completion percentage is not defined:
syntax acceptance, exact CFGs, binding/type fidelity, data flow and the full
Joern framework have different populations/contracts.

| Area | Evidence and present interpretation |
| --- | --- |
| C-oriented CFG compatibility | Broad historical validation exists: the [2026-10-09 audit](cfg_parity.md) covered 8,808 cases / 6,377 unique prepared C/C++ inputs. Raw cache comparison had 8,803 matches and five separately certified original-export recoveries. Those are historical builds, not a current-HEAD full re-certification. |
| Current C++ input acceptance | Frozen 1,225 overlapping prepared source/output inputs: 1,171 parsed, 27 rejected, 27 no methods. The 95.6% parsing rate is specific to this pool and is **not** a Joern-completeness, graph-parity or valid-C++ rate. |
| CPG calls and binding facts | [Call operands](joern_call_port_2026-10-25.md) and [callable objects](joern_callable_port_2026-10-25.md) have independent original CPG controls. They establish only the listed properties/subsets. Matching CFG topology alone cannot detect a wrong receiver or callee. |
| C++ semantic frontend | Substantially incomplete versus Eclipse CDT: general field/member type propagation, inherited/qualified/ADL lookup, conversions, defaults, template instantiation and CV/ref ranking remain gaps. [Ordinary own-field callable evidence](joern_field_callable_port_2026-10-25.md) now connects bounded `a.foo(1)` cases; this is not general CDT member lookup. |
| Data flow | Intraprocedural reaching definitions/DDG are implemented. The [841-function DDG audit](ddg_parity.md) belongs to an older checkpoint; current tests/control comparisons do not re-certify that entire population. No whole-program interprocedural equivalence is claimed. |
| Record initializer containers | [Ordinary record `<clinit>`](joern_record_init_port_2026-10-25.md) now retains bounded array/member initializer ASTs and member-lambda ownership. This is c2cpg graph compatibility, not a C++ runtime initialization model. |
| Lifetime/exception semantics | Some explicit constructors/destructors/try/catch paths exist, but complete implicit object cleanup, RAII/unwinding and standard C++ lifetime semantics are not established. |
| Joern framework breadth | This project supplies native C/C++ parsing, graph construction, CLI/Python and compatibility surfaces. Upstream also has Java, Kotlin, JS, Python and other frontends, its query/runtime ecosystem and passes. These are not replaced by this implementation. |

The useful characterization is a specialized C/C++ graph engine with
substantial compatibility work and a growing, bounded C++ frontend. It is not
a drop-in replacement for all Joern workflows or a full Rust implementation of
CDT. Historical broad C-oriented results and current focused C++ evidence must
stay separate.

Original-Joern parity is itself not proof of complete C++ language semantics:
the current callable controls demonstrate Joern's const-object untyped path
on code accepted by Clang. Compiler/behavior evidence, producer output validity
and evaluator eligibility remain separate checks.

Priority: preserve effects/function coverage; expose missing bindings rather
than invent them; broaden record/member facts beyond ordinary own fields;
then broaden overload/template/lifetime support and re-certify larger frozen
populations. No benchmark score or completion percentage is inferred from
unit-test green or this status table.

Follow-up, 2026-10-26: [bounded member lookup and grouped lambda identities](joern_member_lookup_2026-10-26.md)
now cover ordinary public single-base chains, declaration-scoped field aliases
and CV/mutable evidence. General CDT lookup, templates, complex inheritance
and CV pointer distinctions remain outside that certification.
